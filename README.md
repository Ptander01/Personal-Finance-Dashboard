# Personal Finance Dashboard

A six-tab personal finance dashboard that reads **one JSON file you supply**.
Spending overview with category filtering, peer comparison against public
benchmarks, an income and allocation view, a cash-flow Sankey, multi-year trends,
and a wealth snapshot. Vanilla JavaScript, Chart.js and d3-sankey, built with
Vite. No backend, no accounts, no telemetry — your data is fetched from
`public/data.json` on your own machine and goes nowhere else.

Ships with a synthetic dataset so it runs the moment you clone it. Swap in your
own export and every view follows, including the year selector.

## Quickstart

```bash
npm install
npm run data
npm run dev
```

`npm run data` regenerates `public/data.json` — 1,542 synthetic transactions
across four years, internally consistent and deterministic. It is what you see
before you supply your own.

## Using your own data

1. Read **[docs/DATA-SCHEMA.md](docs/DATA-SCHEMA.md)**. Thirteen top-level keys,
   documented field by field.
2. Read `scripts/generate-sample-data.py` — it builds a complete valid file from
   scratch, so it doubles as executable documentation of the schema.
3. Write your own exporter, from wherever your transactions live, and have it
   emit `public/data.json`.
4. Edit `src/config.js` for the title. Nothing else needs touching.

**`public/data.json` is gitignored.** That is deliberate: this repo should never
hold anyone's real figures, including a fork's.

### The year span is derived, not configured

The year pills and the header range come from the keys of `by_year_total`. A file
covering 2019–2022 produces those pills with no code change.

### What the generator guarantees

Charts do not validate their inputs — an inconsistent file renders confidently
and wrongly. So the generator asserts, before writing:

- monthly totals sum to the yearly total
- subcategories sum to their parent category
- transactions sum to the month they belong to
- `income − expenses == net_savings`

Worth reproducing in your own exporter. These were the checks that caught real
errors while building the sample.

## The tabs

| Tab | What it answers |
|---|---|
| **Overview** | Where the money went. Click a category to filter every chart on the page. |
| **Peer Comparison** | How your spending sits against public benchmarks, by category and as a share of income. |
| **Income & Flow** | What came in, what tax took, what was left, and the allocation across categories. |
| **Cash Flow** | A Sankey from income sources through to category spend, per year. |
| **Trends** | Net income by year, year-over-year category shift, rolling averages. |
| **Wealth** | Balance-sheet snapshot against age-cohort medians. |

## Project layout

```
public/data.json          YOUR DATA — gitignored, generated by the script below
scripts/
  generate-sample-data.py synthetic dataset + the consistency assertions
src/
  config.js               title and locale — the only file you must edit
  main.js                 fetches data.json, hands it to createApp()
  data.js                 every accessor the components use
  app.js                  shell, tabs, year pills (derived from the data)
  components/             overview, benchmark, income, cashflow, trends, wealth
  templates.js            card markup
docs/DATA-SCHEMA.md       the contract
```

## Limits

**Spending-oriented.** Transactions are positive amounts and the model assumes
outflow. Investment positions, debt schedules and income at transaction
granularity are not represented — income enters through the `sankey` and
`benchmarks` sections as annual figures.

**Benchmarks are US-centric.** The comparison figures shipped in the sample are
US national medians and BLS-style averages. They are data, not code — replace
them for another country — but the framing assumes that kind of reference exists.

**The childcare view assumes children.** If that does not apply, remove the card
from `templates.js` rather than filling it with zeros.

**No importer.** Converting a bank or budgeting-app export into this schema is
your step. The schema is documented and the generator shows a working example;
there is no CSV adapter.

**Single currency, no FX.** One currency throughout, formatted from `config.js`.
